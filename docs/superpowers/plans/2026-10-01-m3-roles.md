# M3: roles in core (implementation plan)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `src/roles.rs`. A session claims a role by signing with the role's key. The newest claim
gets a strictly increasing epoch, and calls under any older epoch get `Superseded`. The state can be
snapshotted for M4.

**Architecture:** pure logic in core: no I/O, no clock (`now` is passed in).
- Binding: f1's `validate_chain`.
- Possession: an Ed25519 signature (ring) over domain-separated text.
- Freshness and replay: `replay::ReplayGuard` with `ReplayConfig::default()` (past 5 min, ahead
  1 min).

**Tech stack:** ring, chrono, serde (all already in core).

**Spec:** `docs/superpowers/specs/2026-10-01-m3-roles-design.md`. The PM approved Q1–Q4 as
recommended on 2026-10-01.

## Global constraints

- **Toolchain:** stable, via PowerShell, with `cargo --version` in logs.
- **Version:** no bump; the PM allocates it at the gate.
- **Licence:** every new `.rs` file starts with `// SPDX-License-Identifier: MIT OR Apache-2.0`.
- **Model-agnostic:** no vendor names in core (the M0 guard).
- **Signed text:** `synapse/role-claim/v1\n{global_id}\n{hex nonce}\n{signed_at RFC3339, Secs, Z}`.
- **Freshness:** only `Decision::Deliver(Freshness::Fresh)` is accepted.
  `Deliver(anything else)` gives `ClaimError::Stale`, and `Drop` gives `ClaimError::Replayed`.
- **Epochs:** the first claim is 1. `check` on a never-claimed role gives
  `Superseded { current: 0 }`.

## Review focus

1. **A failed claim must not change any state:** no epoch bump and no consumed nonce. Only a fully
   verified claim records its nonce, so an attacker can't burn a legitimate client's nonce. The
   guard is consulted last, and only after the chain and signature have verified.
2. **The signed text must bind the `global_id` taken from the CERTIFICATE**, not anything the
   caller names separately. A certificate for role A can't produce a claim on role B.
3. **Restore must never lower an epoch:** `restore` followed by `claim` continues from the stored
   epoch.
4. **A signature with the wrong length** (not 64 bytes) is refused, not a panic.
5. **Time skew:** a claim signed 2 minutes in the future (beyond `ahead`) is `Stale`.

### Task 1: Claim, check, current (+ signing helper)

**Files:** create `src/roles.rs`; modify `src/lib.rs` (`pub mod roles;`); test `tests/roles.rs`.

**Interfaces (produced):**
```rust
pub const CLAIM_DOMAIN_TAG: &str = "synapse/role-claim/v1";
pub struct ClaimRequest { pub chain: Vec<AgentCertificate>, pub nonce: [u8; 16],
                          pub signed_at: DateTime<Utc>, pub signature: Vec<u8> }
pub fn claim_signing_input(global_id: &str, nonce: &[u8; 16], signed_at: DateTime<Utc>) -> String;
pub fn sign_claim(identity: &RoleIdentity, nonce: [u8; 16], now: DateTime<Utc>) -> Result<ClaimRequest, ClaimError>;
#[derive(Debug, Clone, PartialEq, Eq)] pub struct Grant { pub global_id: String, pub epoch: u64, pub superseded: Option<u64> }
#[derive(Debug, Clone, PartialEq, Eq)] pub enum ClaimError { Chain(ChainError), BadSignature, Stale, Replayed, NoSigningKey }
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub struct Superseded { pub current: u64 }
pub struct Roles { .. }
impl Roles {
    pub fn new(now: DateTime<Utc>) -> Self;
    pub fn claim(&mut self, req: &ClaimRequest, account_keys: &dyn Fn(&str) -> Option<[u8; 32]>,
                 revoked: &dyn RevocationLookup, now: DateTime<Utc>) -> Result<Grant, ClaimError>;
    pub fn check(&self, global_id: &str, epoch: u64) -> Result<(), Superseded>;
    pub fn current(&self, global_id: &str) -> Option<u64>;
}
```
`ClaimError` and `Superseded` implement `Display` and `Error`, with no key bytes in either.

- [ ] **Step 1: Write the failing tests** in `tests/roles.rs`. The fixture is a temp `Keystore` with
  account `acct` and role `lane`, and `t0 = 2026-10-01T12:00:00Z`.
  - `first_claim_gets_epoch_one_and_a_second_supersedes_it`:
    - claim A gives `Grant { "lane@acct", 1, None }`;
    - claim B gives `Grant { .., 2, Some(1) }`;
    - `check(1)` gives `Err(Superseded{current:2})`, and `check(2)` gives `Ok`.
  - `a_never_claimed_role_is_superseded_at_zero`: `check("x@acct", 1)` gives
    `Err(Superseded{current:0})`, and `current("x@acct")` is `None`.
  - `an_unknown_account_is_refused_and_changes_nothing`: the `account_keys` lookup returns `None`.
    Expect `Err(Chain(UnknownIssuer))`, `current` stays `None`, and then the SAME request succeeds
    with the right lookup, which proves the nonce wasn't consumed.
  - `a_signature_by_another_key_is_refused`: sign with a different role's identity, but put this
    role's chain in the request. Expect `BadSignature`.
  - `a_claim_for_another_role_cannot_reuse_a_certificate`: take role A's signature and role B's chain.
    Expect `BadSignature`, because the signed text names A while the certificate names B.
  - `a_replayed_claim_is_refused_without_a_new_epoch`: the same request twice. The second gives
    `Replayed`, and `current` stays 1.
  - `a_stale_or_future_claim_is_refused`:
    - `signed_at = t0`, checked at `now = t0 + 6min`, gives `Stale`;
    - `signed_at = t0 + 2min`, checked at `now = t0`, gives `Stale`;
    - in both cases there is no epoch.
  - `a_short_signature_is_refused_not_a_panic`: a 10-byte signature gives `BadSignature`.
  - `an_expired_certificate_is_refused`: `now = t0 + 25h`, with the cert issued at t0 and the
    signature at the same `now`. Expect `Chain(Expired)`.
- [ ] **Step 2: Run** `cargo test -p synapse --test roles`. Expected: a compile FAIL (no module).
- [ ] **Step 3: Implement** in this order:
  1. `validate_chain`;
  2. take `global_id`, the signing key and `key_id` from the verified leaf;
  3. verify the signature (`UnparsedPublicKey::new(&ED25519, key).verify`); a wrong length fails
     verification;
  4. `guard.check(key_id, hex(nonce), signed_at, now)`, mapped per the Global constraints;
  5. bump the epoch.

  `Roles` holds a `ReplayGuard` behind interior state. `claim` takes `&mut self`, so it's a plain
  field.
- [ ] **Step 4: Run.** Expected: all PASS.
- [ ] **Step 5: Commit** `feat(roles): claim a role with its key; newest epoch wins (M3)`.
