# M2: persistent keystore (implementation plan)

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a keystore on disk that gives any process a stable `role@account` identity: account key,
role keys, and a locally issued f1 certificate. Plus a `synapse id init|show` CLI.

**Architecture:**
- `src/keystore.rs` lives in the core, behind feature `crypto`. It does file I/O only, and `now` is
  passed in.
- `crates/synapse-cli` holds the `synapse` binary, adapter (c).
- Writes are atomic and create-only, except `cert.pem`. Permissions are checked on every load:
  Unix mode bits, and the Windows ACL.

**Tech stack:**
- ed25519-dalek 2.2 with the `pkcs8` and `pem` features (the account key);
- ring Ed25519 PKCS#8 v2 through `CryptoManager` (role signing);
- `SealingKeyPair` (role sealing);
- windows-sys 0.61 (the ACL check), plus clap and chrono.

**Spec:** `docs/superpowers/specs/2026-10-01-m2-keystore-design.md`. The PM approved Q1–Q4 as
recommended on 2026-10-01.

## Global constraints

- **Toolchain:** run cargo from PowerShell with the stable toolchain bin first on PATH. Print
  `cargo --version` into every log.
- **Version:** do not bump. The PM allocates the version at gate time.
- **Licence:** every new `.rs` file starts with `// SPDX-License-Identifier: MIT OR Apache-2.0`.
- **Model-agnostic:** no vendor names in core (`tests/core_is_model_agnostic.rs` must stay green). The
  CLI is an adapter crate under `crates/`.
- **Secret hygiene:** no key bytes, PEM bodies or key paths in any `Display`, `Debug`, error, log
  line or CLI output. Errors name the ITEM ("account key", "role signing key", …), never a path.
- **Names:** role and account names match `[A-Za-z0-9_-]{1,64}`.
- **Approved values:**
  - home = `$SYNAPSE_HOME`, else `%LOCALAPPDATA%\synapse`, else `$XDG_DATA_HOME/synapse`, else
    `~/.local/share/synapse`;
  - certificate validity 24 h, renewed on load when under 12 h remain;
  - default permissions `send`, `request-ack` and `ack`;
  - Windows: refuse if `Everyone` (S-1-1-0), `Users` (S-1-5-32-545) or `Authenticated Users`
    (S-1-5-11) has any allow ACE that includes read.

## Review focus

1. **A key file must never be overwritten.**
   - The risk: two processes loading the same new role at once both generate keys. The second
     rename would replace the first, and two sessions would hold different keys for one identity.
   - Create-only must mean create-new (`OpenOptions::create_new` on the final name, or a
     rename-no-replace), with the loser re-reading the winner's key. Task 2 tests this with
     threads.
2. **Renewal must be idempotent under the same race:** two renewals of `cert.pem` are both valid
   certificates for the same keys, so replace-on-renew is safe. Assert the keys are unchanged.
3. **A leftover temp file** from a crash must never be read as a key, and it must not block the next
   write.
4. **The Windows ACL check must look at the KEY FILES and the home dir**, not only the dir: a file
   can carry its own explicit ACE.
5. **Error text must not leak the path**, including io::Error's own `Display`, which on some
   platforms includes the path. Map io errors to their `ErrorKind` only.

### Task 2: Roles: keys, certificate, renewal, the create race

**Interfaces (produced):**
```rust
pub const CERT_VALIDITY: chrono::Duration;   // 24 h
pub const RENEW_BELOW: chrono::Duration;     // 12 h
pub struct RoleIdentity {
    pub global_id: String,                   // "<role>@<account>"
    pub crypto: CryptoManager,               // load_private_key + load_sealing_key_pem + set_certificate_chain applied
    pub signing_key_id: String, pub sealing_key_id: String,
    pub not_before: DateTime<Utc>, pub not_after: DateTime<Utc>,
    pub permissions: Vec<Permission>,
    pub chain: Vec<AgentCertificate>,
}
impl Keystore { pub fn role(&self, role: &str, now: DateTime<Utc>) -> Result<RoleIdentity, KeystoreError>; }
```
`impl Debug for RoleIdentity` prints the ids, the window and the permissions only.

- [ ] **Step 1: Write the failing tests** (append to `tests/keystore.rs`):
  - `a_role_is_stable_across_loads`: two `role("synapse", t0)` calls give the same `global_id`
    (`synapse@<acct>`), the same signing and sealing key ids, and the same certificate serial.
  - `a_fresh_certificate_validates_against_the_account_key`: `certificate::validate_chain(&chain,
    &|kid| (kid == acct.key_id).then_some(store.account_public_key()), &NoRevocations, t0)` returns
    Ok. Its subject is `synapse@acct`, its permissions are `[Ack, RequestAck, Send]` (sorted), and its
    window is `[t0, t0+24h]`. Define `NoRevocations` locally in the test.
  - `a_certificate_is_renewed_under_twelve_hours_and_not_before`:
    - at t0+11h, the serial is unchanged;
    - at t0+12h+1s, there is a new serial with window `[now, now+24h]`, and the signing and sealing
      key ids are unchanged;
    - the renewed chain validates.
  - `an_expired_certificate_is_renewed`: at t0+48h, a new serial that validates at t0+48h.
  - `concurrent_first_loads_agree_on_one_key`: 8 threads, each calling `Keystore::open(home)` then
    `.role("race", t0)`. All 8 return the same `signing_key_id` and `sealing_key_id`.
  - `a_garbage_role_key_is_corrupt_and_unnamed`: junk in `roles/x/signing.key.pem` gives
    `Err(Corrupt("role signing key"))`, and the message has no path.
  - `role_names_are_validated`: `role("../evil", t0)` gives `Err(InvalidName)`.
- [ ] **Step 2: Run** them. Expected: a compile FAIL, because `role` isn't defined.
- [ ] **Step 3: Implement.**
  - Signing key: `CryptoManager::new().generate_keypair()`'s private PEM. Sealing key:
    `SealingKeyPair::generate().to_pkcs8_pem()`.
  - Both are written with `write_new`. When it reports "already existed", **read the existing file**:
    the loser of the race adopts the winner's key.
  - The certificate is `AgentCertificate::sign(unsigned, &account_key)` with:
    - version 1;
    - a random 16-byte serial;
    - `issuer_key_id` = the account `key_id`;
    - `subject_label` = the role;
    - `subject_global_id` = `role@account`;
    - the subject keys from the loaded keys;
    - `not_before` = now, `not_after` = now + `CERT_VALIDITY`;
    - permissions `[Send, RequestAck, Ack]`;
    - `may_delegate` 0.
  - `cert.pem` is written with replace semantics (temp file, then rename over). It's (re)issued when
    it's missing, unparsable, has `not_after - now < RENEW_BELOW`, or its subject keys don't match
    the loaded keys.
- [ ] **Step 4: Run.** Expected: all PASS. Run the concurrency test 5 times in a row.
- [ ] **Step 5: Commit** `feat(keystore): role keys and locally issued, auto-renewed certificates (M2)`.

### Task 3: Windows ACL check

**Files:**
- Modify `src/keystore.rs`: add `#[cfg(windows)] fn readable_by_broad_group(path) -> io::Result<bool>`,
  called from `read_checked` and `ensure_dir`.
- Modify `Cargo.toml`: under `[target.'cfg(windows)'.dependencies]`, add
  `windows-sys = { version = "0.61", features = ["Win32_Foundation", "Win32_Security",
  "Win32_Security_Authorization", "Win32_Storage_FileSystem"] }`. Use the newest version, per the
  dependency rule.

- [ ] **Step 1: Write the failing test.** `#[cfg(windows)] a_key_readable_by_everyone_is_refused`:
  - init an account;
  - run `icacls <account.key.pem> /grant *S-1-1-0:R` and assert that icacls exited 0;
  - expect `open` to give `Err(PermissionsTooOpen("account key"))`.

  Also `#[cfg(windows)] a_fresh_store_passes_the_acl_check`. It is the control, and it must be green
  before the check exists and after.
- [ ] **Step 2: Run.** Expected: the refusal test FAILS (open succeeds), and the control PASSES.
- [ ] **Step 3: Implement.**
  - `GetNamedSecurityInfoW(path, SE_FILE_OBJECT, DACL_SECURITY_INFORMATION, …)`.
  - Walk the ACEs with `GetAce`. For each `ACCESS_ALLOWED_ACE_TYPE` whose `Mask` intersects
    `FILE_READ_DATA | GENERIC_READ | GENERIC_ALL`, compare its SID with `EqualSid` against
    well-known SIDs built with `CreateWellKnownSid`: `WinWorldSid`, `WinBuiltinUsersSid` and
    `WinAuthenticatedUserSid`.
  - Free the descriptor with `LocalFree`.
  - A null DACL means everyone has access, so refuse it.
- [ ] **Step 4: Run.** Expected: both PASS, and the full `tests/keystore.rs` stays green.
- [ ] **Step 5: Commit** `feat(keystore): refuse keys readable by broad Windows groups (M2)`.

**Interfaces:**
- `synapse id init --account <name>` exits 0 and prints exactly two lines, `account: <name>` and
  `account key id: <hex>`.
- If the account exists, it exits 2 with `error: an account already exists`.
- `synapse id show` prints `account: …` and `account key id: …`.
- `synapse id show --role <r>` adds:
  - `identity: <r>@<acct>`;
  - `signing key id: …`;
  - `sealing key id: …`;
  - `certificate valid: <not_before RFC3339> to <not_after RFC3339>`;
  - `permissions: send, request-ack, ack`.
- The home comes from `default_home()`, so the tests set `SYNAPSE_HOME`.
- Any keystore error exits 2 with `error: <Display>`.

    identity line reads `worker@acct`, and the signing key id is stable across the two shows.
  - `init_twice_is_refused_with_exit_2`.
  - `no_output_ever_contains_secrets_or_paths`: run every command above, capturing stdout and stderr,
