# Sealing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Encrypt a `SecureMessage` body to the recipient's pinned X25519 key (HPKE base mode). The
receiver gets `Payload::{Plain, Opened, CouldNotOpen}`, and the self-decrypting `encrypt_message` and
`decrypt_message` are removed.

**Architecture:**
- A new `src/sealing.rs` holds the suite, the key types (PKCS#8 and SPKI PEM), the authenticated
  data, `seal`, `open`, `Payload` and `OpenError`.
- `CryptoManager` holds this node's sealing key.
- `TrustStore` pins peers' sealing keys.
- `TransportManager` opens every received message.
- `synapse-mcp` always seals.

**Tech Stack:** `hpke` 0.14.1 (`default-features = false`, features `alloc`, `getrandom`, `x25519`,
`chacha`), inside the existing `crypto` feature, plus `pem` 3 and `sha2`. Python 3.14 with
`cryptography` 50.0.1 is used only for the independent check, and is not committed.

**Spec:** `docs/superpowers/specs/2026-09-17-sealing-design.md`

## Global Constraints

- **Branch:** `feat/sealing`, stacked on `feat/mcp-surface`. Not merged until the PM's daily pass
  (CireSnave's throttle policy).
- **Suite:** `hpke::kem::X25519HkdfSha256`, `hpke::kdf::HkdfSha256`, `hpke::aead::ChaCha20Poly1305`,
  `OpModeS::Base` and `OpModeR::Base`.
- **Exact strings:** `info` = `synapse/seal/v1`; the authenticated-data tag = `synapse/seal-aad/v1`;
  format version byte `0x01`.
- **The marker:** a signed metadata key `synapse.sealed` = `v1`. **Deviation from the spec, recorded
  there:** receivers use this marker to decide whether a body is sealed, instead of sniffing its first
  byte. A plaintext body can legitimately start with `0x01`, so byte sniffing is ambiguous. Relays
  can't strip the marker without breaking the signature.
- **Keys:**
  - never derive X25519 from Ed25519;
  - private keys as PKCS#8 v1 (`302e020100300506032b656e04220420` ‖ 32 bytes);
  - public keys as SPKI (`302a300506032b656e032100` ‖ 32 bytes).
- **Secret hygiene:** no private sealing key bytes or key path in any `Debug` output, error, log line or
  tool output.
- **Checks:**
  - `cargo test --no-fail-fast` keeps the failing set `{test_transport_error_handling}`;
  - `cargo fmt -- --check` exits 0;
  - `cargo clippy -- -D warnings` exits 0;
  - clippy exits 0 on each new or changed test target.
- **Firewall:** tests bind loopback only. The final full run happens in a **fresh** target directory,
  and the Windows Firewall event 2097 count for its window is reported.
- **No version bump.**

  with `Display` giving snake_case names.

- [ ] **Step 1:** Write the tests listed above in `tests/sealing.rs`. They build messages in memory,
  and a `TrustStore` pins Alice's signing key under her id and under an alias.
- [ ] **Step 2:** Run them and check that they fail to compile (`synapse::sealing` is missing).
- [ ] **Step 3:** Implement `src/sealing.rs`:
  - `seal` refuses unless the level is `Private` or `Secure` (`SynapseError::EncryptionError`), and
    refuses if the marker is already present.
  - It computes the authenticated data, calls
    `single_shot_seal::<ChaCha20Poly1305, HkdfSha256, X25519HkdfSha256>`, writes
    `0x01 ‖ enc ‖ ct`, and inserts the marker.

- [ ] **Step 5:** Commit: `feat(sealing): HPKE seal/open of the message body (P2d)`.
